# IT-термины перед C#

Статичный учебный сервис для студентов, которые только начинают изучать C# и пока не уверенно понимают базовые IT-термины.

Сейчас в базе 396 терминов: базовое IT-окружение, жизненный цикл ПО, C#/.NET, Git/GitHub, выполнение программы под капотом, файлы сборки проекта, короткий обзор ООП, переменные, типы данных, ввод, операции, преобразования, условия, ветвление, циклы, одномерные массивы, методы, строки, отсутствие значения, отладка, проверка алгоритмов, обработка исключений и текстовые файлы.

## Что есть

- Карточки с тренировкой: термин на одной стороне, пояснение на другой.
- В карточках кнопка `Повторить позже` отправляет текущую карточку в конец колоды, а `Понял` двигает прогресс вперед.
- Тесты в двух направлениях: термин -> пояснение и пояснение -> термин.
- 478 разобранных примеров C# для терминов из ЛБ 4–14. Они видны в справочнике и на обороте карточек.
- У 171 задания есть скрытые альтернативные версии: у 105 — по восемь, у 60 — по одиннадцать, у одного — пять, у одного — четыре и у четырёх — по три (1521 дополнительный вопрос). Меняются не только числа, но и операции, границы, порядок присваиваний, расположение break/continue, обращения к массиву, использование результата метода, тип ошибки, входные данные и записываемые файлы. На экране остаются четыре варианта ответа; они перемешиваются. Вопрос, ввод, ответ и пояснение выбираются вместе.
- При следующих запусках для задания выбирается ещё не использованная версия. История выбора хранится в этом браузере в `code-version-history-v1`; после полного перебора начинается новый круг без немедленного повтора последней версии. При недоступном хранилище выбор без повторов работает в пределах текущего посещения. Это история выбранных для тренировок версий, а не оценка знаний.
- Отдельная практика «Понимаю код» с вопросами о результате, строке кода и причинах ошибки; после ответа показывается объяснение. В каждом вопросе прямо указано, что выбрать: вывод, итоговое значение переменной, число выполнений строки, фрагмент для пропуска, причину ошибки, действие отладчика или тестовые данные. Для нескольких строк вывода оговаривается их порядок; для отладки — место паузы и момент наблюдения.
- «Учим терминал» — бета-тренажёр из 20 уроков по работе с файлами, запуску проекта и Git. Доступны PowerShell на Windows, Bash на Linux, песочница, история команд, подсказки и отметки о пройденных уроках для каждой оболочки. Поддерживаемые флаги перечислены в справке под консолью. Файлы и репозиторий симулируются в браузере.
- «Найди ошибку» содержит 250 карточек, по 25 для ЛБ 4–9 и 11–14. В одну тренировку случайно выбираются 5 карточек нужной лабораторной. На лицевой стороне условие и код с одной ошибкой, на обороте исправленный код с выделенной строкой, пояснение и ожидаемый результат. ЛБ 11 включает строки и null; ЛБ 12 — проверку алгоритмов; ЛБ 13 — исключения и сохранение остатка мест; ЛБ 14 — методы File, пути, расширение массива, ввод названия и сохранность списка при ошибках чтения и записи. Таймера нет. После просмотра решения студент выбирает «Нашёл сам» или «Нужно повторить». Самооценка сохраняется, трудные карточки доступны через фильтр повторения. Если отмеченных карточек меньше пяти, показываются все отмеченные.
- Перед стартом «Понимаю код» доступны две независимые настройки. «Скрывать варианты ответа» оставляет вопрос и код без вариантов до нажатия «Показать варианты». Таймер идёт с начала вопроса; открытие вариантов его не перезапускает. «Скрывать проверку до конца теста» убирает подсветку правильности, пояснения и счётчики верных/неверных ответов до завершения всей подборки. Выбранный вариант отмечается нейтральной рамкой. В этом режиме досрочного завершения нет; после последнего задания появляются итог и разбор каждого ответа с кодом, вводом, выбранным вариантом, правильным ответом и объяснением. Обе настройки можно включать вместе. Они фиксируются на время попытки; по умолчанию выключены.
- В практике «Понимаю код» на каждое задание даётся 90 секунд. По истечении времени задание не приносит балл, повторный ответ недоступен. При обычной проверке открываются правильный вариант и объяснение, даже если варианты до этого были скрыты. При скрытой проверке результат остаётся скрытым до конца попытки. Следующее задание открывается кнопкой.
- Для зачёта в «Понимаю код» нужно не менее 50% правильных от первоначального числа вопросов (`ceil(N / 2)`). В обычной попытке из 10 вопросов после 5 правильных сразу показывается зачёт, после 6 неправильных — незачёт. Пять ошибок ещё оставляют возможность получить 5 правильных из 10. При скрытой проверке результат определяется после всей подборки. Истечение времени считается неправильным ответом. После завершения видны числа правильных, неправильных и неотвеченных вопросов. В обычном режиме последний код и пояснение остаются для разбора; в режиме скрытой проверки доступен разбор всех ответов текущей попытки. Неотвеченные задания не записываются в ошибки или прогресс.
- В «Найди ошибку» зачёт появляется после 3 отметок «Нашёл сам». Попытка завершается с незачётом, когда оставшихся карточек уже недостаточно для трёх таких отметок (в обычной подборке из 5 — после 3 «Нужно повторить»). Это самооценка студента. Повторение из 1–2 карточек проходит до конца без выставления зачёта или незачёта.
- Группировка по темам и колодам.
- Справочник с поиском, сортировкой и фильтрами.
- Цветные метки в справочнике для тем, колод и лабораторных работ (ЛБ 1–14).
- Фильтр по меткам, включая быстрый отбор терминов по лабораторной работе.
- Темная тема.
- Предупреждение при выходе из активной тренировки.
- Прогресс хранится в этом браузере: ответы в карточках, тесте и практике, число попыток и ошибки. На главной видны пройденные термины и список для повторения. В каждом режиме есть фильтр повторения в выбранной теме/подборке; карточки могут повторять термины из ошибок всех режимов. Верный ответ снимает отметку ошибки в соответствующем режиме, история попыток остаётся.
- В обычном тесте после ответа показаны правильный вариант и определение термина. Переход — кнопкой «Далее», без автоматического таймера.
- Ответы записываются сразу, включая незавершённые тренировки. После перезагрузки можно начать новую тренировку с учётом сохранённых ошибок; текущий вопрос не восстанавливается. Прогресс не переносится между устройствами и удаляется при очистке данных сайта.

## Уровень примеров

Примеры следуют темам курса. Ветвление появляется в ЛБ 6, массивы, foreach и int.TryParse/out — в ЛБ 8, пользовательские функции и формат F2 — в ЛБ 9. ЛБ 10 вводит явный Main, перегрузки, необязательные параметры, именованные аргументы и методы Array.Copy, Array.Sort, Array.Reverse и Array.IndexOf.

Для заданий с вводом используются указанные данные, включая команду завершения цикла. В ЛБ 8 добавлена проверка неправильного ввода через int.TryParse и повторный запрос. Окончание потока ввода вводится в ЛБ 11. try/catch/finally, throw и создание объектов исключений появляются в ЛБ 13.
В ЛБ 11 вводятся string?, null, #nullable enable и int?. В метаданных примеров и вопросов пустая строка ввода означает обычный Enter, а null — уже завершённый входной поток. Эти состояния отдельно подписываются в интерфейсе и проверяются при выполнении учебных примеров.

ЛБ 12 подготовлена по лабораторной «Отладка и проверка алгоритмов»: две словарные колоды по 10 терминов, две колоды практики по 10 вопросов и 25 карточек «Найди ошибку». Покрыты точки останова, текущая инструкция, F10/F11/Shift+F11/F5, Locals, Watch, стек и кадры вызовов, ожидаемый и фактический результат, контрпример и повторная проверка. Сочетания клавиш описаны для Visual Studio из лабораторной; в других профилях настройки могут отличаться. Вопросы про отладчик задают конкретное место паузы и условия шага; в браузере отладчик не запускается. Короткие исполняемые фрагменты используют локальные функции в Program.cs; в исходной лабораторной методы находятся в class Program рядом с Main. Намеренно ошибочные примеры отдельно поясняют фактический и правильный результат. Основные проверки рассчитаны на непустой массив; пустой массив явно отмечен как дополнительная часть. Наборы содержат не более четырёх элементов и позволяют проверить причину ошибки без длинных вычислений.

ЛБ 13 подготовлена по лабораторной «Обработка исключений в C#»: три словарные колоды по 10 терминов, три колоды практики по 10 вопросов, 15 скрытых версий и 25 карточек «Найди ошибку». Покрыты прерывание try, конкретный catch перед общим, finally при успехе и отказе, throw из метода, отличие new от throw, nameof и Message. Примеры ReserveSeats отделяют TryParse от проверки аргументов и текущего остатка, сохраняют результат только после успеха и показывают отсутствие автоматического отката. Есть повторная попытка в коротком цикле, пустой обработчик, команда выхода с пробелами и разным регистром, null и пустой ввод. Parse используется в отдельных примерах механики исключений; обычный ввод бронирования проверяется TryParse. В небольших фрагментах начальный остаток явно указан, а полный сценарий лабораторной начинается с 10. Отмена бронирования отмечена как дополнительная часть. Собственные классы исключений и рекурсия не вводятся.

ЛБ 14 подготовлена по лабораторной «Работа с текстовыми файлами в C#»: три словарные колоды по 10 терминов, три колоды практики по 10 вопросов, 9 скрытых версий и 25 карточек «Найди ошибку». Покрыты ReadAllText/WriteAllText и ReadAllLines/WriteAllLines, перезапись, пустой и отсутствующий файл, рабочая папка и GetFullPath, string[], Array.Empty<string>(), копирование при расширении и замена ссылки. В задачах видно начальное содержимое файла или прямо указано его отсутствие. Вопросы о конкретном Windows-пути явно задают рабочую папку; в общих примерах полный путь описан словами, поскольку зависит от запуска. Ошибка доступа в одном примере явно моделируется через throw, остальные файловые операции проверяются на настоящих временных файлах. Загрузка различает первый запуск и остальные ошибки, сохранение сообщает об успехе после записи, сохраняет массив при отказе и выполняется по команде 3. Названия обрезаются по краям, пустые и пробельные названия отклоняются, null завершает ввод. Фрагменты команд могут отдельно читать файл для проверки результата; это отмечено в условии и не является дополнительной командой меню.

## Где менять термины

Все термины находятся в `terms-content.js` в массиве `topics`. Примеры и задания находятся в `code-content.js` в массиве `codeLessons`. Каждый элемент связан с термином парой `deckId` + `term`; для нового задания сначала добавьте соответствующий термин в колоду.

Карточки «Найди ошибку» находятся отдельно в `bug-content.js` (`bugCards`). У каждой стабильный `id`, лабораторная `lab`, связь со словарём `deckId` + `term`, условие `prompt`, код `brokenCode` и `fixedCode`, номер исправленной строки `changedLine` (с единицы), пояснение и `expectedResult`. Тип `kind` — compile, runtime или logic — показывается только вместе с решением. Пара программ должна отличаться ровно одной строкой. Для логических ошибок укажите `brokenResult`, для ошибок выполнения — `exceptionType`. Команда `node tests/verify-bug-cards.mjs` с установленным .NET SDK проверяет все исправленные программы и отдельно подтверждает заявленные ошибки: отказ компиляции, необработанное исключение или неправильный вывод. До ЛБ 13 учебный код не содержит обработки исключений; в ЛБ 13 проверяется также выбор catch и сохранение состояния после перехвата.

В `code-content.js` массив `codeDecks` задаёт колоды практики (`id`, `lab`, `title`), а поле `codeDeckId` каждого задания связывает его с одной колодой. В колоде должно быть 5–10 примеров. Несколько заданий могут ссылаться на один термин через `deckId` + `term`; каждое задание имеет уникальный стабильный `id`. Ошибки практики учитываются отдельно по `id`, чтобы ответ в одном примере не снимал ошибку другого. Старые записи по термину автоматически относятся к исходному заданию. В справочнике показаны все связанные примеры; на карточке — первый.

Фрагменты C# показаны как текст: сайт не запускает их в браузере. Для задания можно указать `challengeInput`, а правильный вариант задаётся индексом `correctIndex` в массиве `options`. Ответ должен сопровождаться пояснением `explanation`. Дополнительные версии хранятся в `variants`: у каждой свои `challengeCode`, `prompt`, `options`, `correctIndex`, `explanation` и `challengeResult` для проверки через .NET. Каждой версии задаётся отдельный `prompt`, чтобы инструкция соответствовала именно её коду. Связь со словарём и колодой наследуется от основного задания. Не меняйте основное задание при перемешивании ответов.

Условие задания должно называть одно действие выбора и точно описывать объект ответа. Если варианты — итоговая сумма, спрашивайте значение sum после цикла. Если предлагаются массивы, укажите, какой аргумент ими заменяется и какую ошибку должен обнаружить набор. В задании с пропуском назовите маркер /* ??? */ и ожидаемый вывод; при нескольких строках явно задайте порядок. В заданиях с отладчиком уточните инструкцию, перед которой стоит пауза, уже выполненный шаг и контекст просматриваемой переменной. Проверки данных требуют самостоятельный prompt у каждой версии, явное действие «Выберите» и указание порядка многострочного ответа.

Для вопросов «Заполните пропуск» используется маркер `/* ??? */` и поле `solutionResult`. Проверка подставляет выбранный правильный вариант в маркер, компилирует полученный C# и сверяет вывод с `solutionResult`.

Проверка данных и поведения тренировок: `node --test tests/*.test.mjs`. Если установлен .NET SDK, команда `node tests/verify-examples.mjs` компилирует все примеры в временном проекте и сверяет их вывод, а также ответы новых исполняемых заданий из поля `challengeResult`. Проверка задаёт InvariantCulture и для вычислений, и для перехваченного вывода: в ожидаемых результатах используется точка. В реальной консоли десятичный разделитель зависит от настроек системы; вопросы с F2 и дробным результатом это поясняют.

Файловые операции вводятся в ЛБ 14. Проверки примеров, исправленных/ошибочных программ и числа проходов выполняют каждый фрагмент в отдельной временной рабочей папке. Это изолирует одинаковые имена demo.txt и shopping.txt и гарантирует заявленное отсутствие файлов. Папки удаляются вместе с временным проектом; файлы сайта не используются для учебных операций. Для примера с зависящим от среды полным путём поле `examplePathResult` задаёт относительное имя, с которым сверяется фактический путь; `.` означает текущую рабочую папку. В справочнике `exampleResult` описывает такой вывод словами.

Команда `node tests/verify-loop-budget.mjs` с .NET SDK отдельно проверяет объём ручной трассировки. Через Roslyn она вставляет счётчики в тела циклов и запускает все примеры и версии вопросов с заданными входными данными, включая исправленные карточки ошибок. Лимит для ЛБ 7 — четыре выполнения одиночного тела или восемь суммарно для вложенных циклов; для остальных лабораторных — десять суммарно, включая повторные вызовы методов. Проверка обнаруживает рост числа шагов даже при небольших числах в границах.

Команда `node tests/verify-lab13.mjs` с .NET SDK запускает показанный в примере ЛБ 13 код одной попытки с общим остатком, изначально равным 10. Проверяются по порядку все 11 строк таблицы лабораторной и отдельно конец ввода: вывод, изменение или сохранение остатка и ровно одно сообщение finally на каждый вызов метода. Код метода и проверки берутся из учебного примера, чтобы проверять опубликованную логику.

Команда `node tests/verify-lab14.mjs` с .NET SDK проверяет сценарий списка покупок: первый запуск без файла, удаление крайних пробелов, отказ от пробельного названия, сохранение и повторную загрузку, перезапись без дублей, потерю только несохранённого добавления после повторной загрузки, пустой файл, ошибки чтения/записи и зависимость относительного пути от рабочей папки. Методы загрузки, добавления и сохранения берутся из опубликованных примеров; все файлы создаются во временном проекте.

Структура:

```js
{
  id: "topic-id",
  title: "Название темы",
  description: "Описание темы",
  decks: [
    {
      id: "deck-id",
      title: "Название колоды",
      terms: [
        {
          term: "Термин",
          definition: "Пояснение"
        }
      ]
    }
  ]
}
```

Рекомендуемый размер колоды для новичков: 10-12 терминов.

## Как открыть

Можно просто открыть `index.html` в браузере.

Для локальной проверки через простой сервер:

```bash
python -m http.server 5507
```

После этого открыть:

```text
http://127.0.0.1:5507/
```

## GitHub Pages

После изменения терминов, примеров, логики или стилей выполните `node scripts/update-assets.mjs`. Команда обновляет версию всех CSS/JS-подключений в `index.html` по содержимому файлов. Это позволяет браузеру загрузить новую базу после публикации, даже если предыдущие файлы ещё хранятся в кэше. Добавляйте обновлённый `index.html` в тот же коммит. Проверка `node --test tests/*.test.mjs` обнаруживает устаревшую версию; отдельно можно выполнить `node scripts/update-assets.mjs --check`.

Для публикации достаточно положить `index.html`, `styles.css`, `terms-content.js`, `code-content.js`, `bug-content.js`, `terminal-engine.js`, `terminal.js`, `app.js` и `README.md` в репозиторий GitHub, затем включить GitHub Pages для нужной ветки и папки.
